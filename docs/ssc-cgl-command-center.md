# SSC CGL Command Center

The React frontend is a focused workspace for Tier I (Prelims) and Tier II (Mains). The selected stage is kept in the existing device settings; switching it updates the dashboard, mock formats, practice subjects, PYQ/CA coverage and stage-specific analytics without deleting local learner history.

## Connect the service and content

1. Configure and run the Express/PostgreSQL backend as described in [database setup](ssc-cgl-database.md), then apply the additive catalog, PYQ, current-affairs and master/player migrations as needed (`npm run migrate:master` applies 005 and additive 006). Never edit an applied migration or run the guarded legacy-bank reset without a backup and explicit approval. No migration runs automatically on frontend startup.
2. For local development, run the backend on port 4000 and `npm run dev` at the repository root; Vite proxies `/api` to the backend. For deployment, configure a same-origin API proxy or the public `VITE_API_URL` for the actual backend, plus a stable backend `JWT_SECRET` and database connection. A Vite build does not deploy the backend.
3. The migrations and syllabus catalogue do **not** publish questions. Follow the source rights and review procedures in [master assembler](ssc-cgl-master-assembler.md), [PYQ vault](ssc-cgl-pyq-ai.md) and [current affairs](ssc-cgl-current-affairs.md). Unpublished or insufficient content stays pending, and an unreachable service is shown as unavailable rather than an empty or available bank.
4. Google/Firebase sign-in and the email/password practice account are separate. Create or sign in to the latter from Profile to prepare and review server-owned sessions. Account creation requires a configured backend; it does not migrate or overwrite existing on-device attempts.

## How the workspace works

- Full mocks, sectionals and 15–30 question subject drills use the master assembler. Tier-I topic/difficulty quotas are the user-approved **editorial practice profile**, not official SSC topic frequencies. The Tier-II MCQ mock excludes the separate qualifying DEST.
- PYQ filters cover cycle years 2021–2025, stage and published shifts; chapter mode uses only published, derivative-permitted content. A fixed shift paper stays intact and flags previously seen questions. A chapter drill can fail if the requested exact count cannot be formed without splitting a set.
- CA offers twelve months and annual slots for 2025 and 2026, plus Awards, Sports, Schemes, Defence (military exercises) and Index (rankings/indexes) category filters. Category drills use the same fixed-source master lifecycle and flag repeats. A stale category snapshot displays its covered-through date. The dashboard capsule shows the latest published source-backed reviewed event with its actual event date, or a pending state; it does not invent a daily fact.
- In Mock Test Hub, the default **requested exam-hall practice** profile uses one 60-minute Tier-I full timer with free subject navigation and 60/60/15-minute Tier-II full section locks. Section I/II can be ended early in practice mode; final submission unlocks in Section III. Tier-II sectionals allow free subject navigation within their single section. Shift papers retain their source duration; chapter-wise PYQ uses one minute per question. CA monthly/annual/category drills use 30/60/15 minutes. Micro drills remain untimed. These requested timings are **not** the 2026 notice module locks. Select the separate notice-based profile to use the existing official timing snapshot; already prepared/active sessions keep their original profile.
- The exam player is an ExamEdge practice interface inspired by common computer-based-test controls, not an official TCS product. It offers bilingual question switching, a five-state palette, passage/data split view and mobile passage panel. Structured DI data is shown as accessible tables when its shape is recognized, with a structured fallback for other data; supplied chart images remain images. Preparing reserves questions for 30 minutes. The server controls the clock and delivers only the current unlocked period; the display accounts for browser sleep and rechecks the server after returning to the page. API responses are marked no-store to prevent stale session or review data from being cached. Answers, review flags and visited states sync as the learner works; explanations remain hidden until submission. Submitting early scores undelivered questions as skipped. An expired session must be submitted to see review.
- Progress is also saved in local storage per backend account/mock, including selected option indices, review flags and question timing, but never question text, answer keys or credentials. Visible, focused question time is accumulated in milliseconds and synced to the backend per device. It is client-reported and may be approximate after crashes, lost storage or overlapping tabs; it is not used for scoring. A refresh can restore locally pending work, and an older server refresh cannot overwrite a newer locally acknowledged choice. A failed background clock check warns while the locally running period remains open; a device without storage, a prolonged outage, or a server-locked/expired section cannot guarantee recovery of unsynced changes. The player warns when work is pending; reconnect before a section ends. Resetting device data removes unsynced local progress, not synced backend history.
- Stage totals count all submitted master sessions. The daily streak uses sessions with at least one selected answer and Asia/Kolkata calendar days. The radar and weak-topic queue use up to the 20 latest reviewed sessions in the selected stage, and correctness only for answered, delivered, non-withdrawn questions. Pace uses the recorded foreground time, or a dash where timing is unavailable.
- Submitted master mocks open a responsive post-mock review immediately and from history. Tier II separates the /390 Paper-I merit component from the /60 Computer minimum check (UR defaults to 18; other category minimums can be chosen on-screen). A badge is a basic practice comparison, not a post-specific or final qualification. An undelivered or subsequently withdrawn section is not assessed. Sectional and shortened mocks are not scaled to full-paper totals.
- Full Tier-I review shows raw /200 scores and per-subject **personal** targets, not official subject cutoffs. Targets are kept on this device and scoped to the backend account; clearing device data removes them. The optional 2–8-shift histogram simulation uses only learner-provided aggregate counts, adds the learner once to Shift 1 and never stores the inputs; see [master analytics](ssc-cgl-master-assembler.md#post-mock-analytics-and-optional-shift-simulation) for validation, limitations and the SSC method link. Values are unavailable until input is supplied and are not official results or predictions.
- Review includes recorded focused-time totals and averages by correct, wrong and skipped, strictly-over-2×-ideal flags, outcome/subject/slowest/trap filters, and keyboard-accessible Basic Concept / 20-Sec Exam Trick tabs. Time not recorded is unknown, and withdrawn, void or undelivered questions do not contribute to timed analytics. Older locally recorded times fill missing server timing on the same account/device and are labelled device-only, without double-counting synced durations. Solutions and CA boosters appear only when reviewed content is available; no substitute content is invented.
- Older local attempts remain visible in Profile; new backend sessions and analytics belong to the separate practice account. Some new interface text is English; bilingual question text uses the selected language when available.

See [DEST and AI Mentor](ssc-cgl-dest-mentor.md) for practice scoring, privacy, rights and backend configuration.
